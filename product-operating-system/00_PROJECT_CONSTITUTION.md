# 00 — Project Constitution

**Authority:** Supreme product law  
**Source:** Restored from `docs/PRODUCT-CONSTITUTION.md` (2026-07-02)

Six rules every product decision must pass.

---

## 1. Produkten leder

The user never has to guess the next step. The app shows what is meaningful next — not a menu of possibilities.

**Test:** Can a new parent open Hem and know what to do without instructions?

---

## 2. Produkten överraskar inte

Nothing feels unexpected or unexplained. Every screen is a natural continuation.

**Test:** Would a parent wonder "why am I seeing this now?" — if yes, we failed.

---

## 3. Produkten visar alltid nästa steg

There is always a clear next step — or a clear reason nothing is needed now. Empty states are forbidden.

**Test:** Empty screen, dead button, or dead-end path?

---

## 4. Produkten minskar osäkerhet

After every action the parent feels: *"I seem to be doing the right thing."*

**Test:** Does copy or UI confirm the family is on the right path?

---

## 5. Produkten känns färdig

After signup the app feels more complete than before — not an empty tool waiting for configuration.

**Test:** Does something already feel done for the family?

---

## 6. Inga magiska tal (No Magic Numbers)

Progression thresholds must derive from intended experience and pacing — **configurable via data** (experience pack manifest, server config), not hardcoded in core engine or client.

**Test:** Can thresholds change by pack adjustment without core engine deploy?

**Operational authority:** `.ai/product/WORLD_DESIGN_BIBLE.md` (Progression Nodes).

---

## Supreme laws (non-negotiable)

- **Reality wins** — completion before celebration (G-01)
- **Child protagonist** — child acts; parent supports (P-02)
- **One Journey authority** for "what's next" (PA-01)
- **Stars not purchasable** (R-02)

See domain docs 04–07 for rule IDs.
